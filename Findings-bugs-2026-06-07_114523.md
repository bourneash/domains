## 🔴 Critical

- [ ] **[ops]** 4 of 8 live sites (aliencouncil, reviewtattoo, ultrarough, weapontester) still on host cron — proven single point of failure after 2026-05-17 wipeout silenced cf-stats for 9 days with no alert. If the host crontab is wiped, content stops publishing and there's no automated detection until a human notices traffic decay. — `HOUSEKEEPING_PROPOSALS.md §1.1` — **impact: silent revenue loss, content rot on 50% of live fleet**

- [ ] **[security]** Shared `.env` at repo root is passed as read-only mount into `domain-developer` containers, but it contains the account-scoped Cloudflare API token + affiliate credentials — a single compromised dev container (via RCE in a site's Node deps) can exfiltrate the token, which controls ALL zones, workers, and DNS across the entire fleet. No per-site least-privilege token scoping exists. — `/home/jesse/projects/domains/.env`, `tools/domain-developer/docker-compose.yml` — **impact: full fleet takeover from one compromised site**

## 🟠 High

- [ ] **[ops]** Worker-name drift between local `wrangler.jsonc` and the deployed CF worker name is invisible until a deploy silently goes to the wrong resource — xxxtea was broken for 16 days before caught. No automated check exists in CI, deployment-tester, or site-tracker to flag this mismatch. — `HOUSEKEEPING_PROPOSALS.md §2.4`, `sites/xxxtea.com/site/wrangler.jsonc` — **impact: silent deploy failures, orphaned workers accumulate**

- [ ] **[ops]** No dead-man-switch on ops role health: `ops/board/last-run.json` is written by roles, but nothing raises an alert if a site's last-run timestamp goes stale (e.g., 48h with no successful run). The Slack notify only fires on individual role failure — it won't catch a cron container that exits and never restarts. — `tools/status`, `sites/americastrikes.com/ops/scripts/run-role.sh` — **impact: publishing loop silently stops, no human paged**

- [ ] **[data]** `sites.yml` (site-tracker source of truth) and `DOMAINS_INDEX.md` (human-readable portfolio manifest) are manually maintained in parallel and drift. There is no enforcement that they stay in sync. A site added to one but not the other causes silent gaps in site-tracker collection and Grafana coverage. — `tools/site-tracker/sites.yml`, `/home/jesse/projects/domains/DOMAINS_INDEX.md` — **impact: new sites invisible to monitoring until manually wired**

- [ ] **[ci]** CF Workers Builds bot opens PRs on some repos; no automated check exists to detect stale bot PRs. One sat 24h unmerged blocking a deploy. No alerting or auto-merge rule is configured for bot-authored dependency PRs. — `HOUSEKEEPING_PROPOSALS.md §2.1` — **impact: deploy pipeline stalls silently**

- [ ] **[build]** americastrikes.com still uses Tailwind v3 and the old adapter path (`dist/server/wrangler.json`) while FLEET_STANDARD mandates Tailwind v4 + `dist/client/wrangler.json` (adapter v13.6+). The site deploys fine today, but a toolchain or adapter update could silently break the deploy command if not migrated. — `sites/americastrikes.com/site/package.json`, `FLEET_STANDARD.md` — **impact: fleet drift makes shared tooling changes risky**

## 🟡 Medium

- [ ] **[ops]** Submodule pointers in the parent repo perpetually show `+` prefix (diverged from recorded commit). No automation bumps them after ops roles push to site repos. A `git submodule update --remote` run at the wrong time could overwrite uncommitted work in a site worktree. — `HOUSEKEEPING_PROPOSALS.md §1.3` — **impact: parent repo git state is always dirty; confusing for any tooling that reads submodule state**

- [ ] **[ops]** sinderella.org and ultrarough.com `ops/board/last-run.json` is either missing or stale per QUICKSTART notes — meaning `tools/status --ops` shows no data for these sites and silent failure is indistinguishable from "never ran." — `tools/QUICKSTART.md` — **impact: ops health dashboard has blind spots on 2 of 8 sites**

- [ ] **[data]** cf-stats stores daily JSONL files with no retention policy or size cap. At ~8760 lines/year per account, the files grow indefinitely and the SQLite DB the Grafana ingest builds will accumulate without pruning. No housekeeping job exists. — `tools/cf-stats/`, `tools/cf-grafana/ingest.py` — **impact: disk growth; query perf degrades over time**

- [ ] **[ops]** `tools/deployment-tester/` serial-bumps `.deploy-probe` and pushes to verify Workers Builds wiring, but it does not restore the file to its original value if verification fails partway through (e.g., CF API timeout after push). Leaves the site with a meaningless dirty commit that must be cleaned manually. — `tools/deployment-tester/` — **impact: manual cleanup required after interrupted test runs**

- [ ] **[security]** `tools/social-setup/` writes platform credentials to `ops/social/.<platform>-creds` files inside site repos. These paths are presumably gitignored, but if a `.gitignore` is missing or incomplete in a site, credentials could be committed and pushed to the public GitHub repo. No guard or pre-commit hook enforces this. — `tools/social-setup/`, site `.gitignore` files — **impact: credential exposure in public repos**
