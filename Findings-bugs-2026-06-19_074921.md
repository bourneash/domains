## 🟠 High

- [ ] **[backend]** `revert` endpoint accepts empty string as valid running crontab and wipes disk — `containerCrontab` returns `''` (not `null`) when `docker exec cat` succeeds but produces no output; the handler only guards `if (running === null)`, so an empty result passes through and `writeFileSync` overwrites the disk crontab with blank content — `server/server.js:180-194` / `server/docker.js:115-122` — fix: also reject when `running` is falsy or empty string before writing

- [ ] **[backend]** `rebuildCron` has no timeout — `spawn('bash', ['-lc', 'docker compose build cron && ...'], { cwd })` runs unbounded; a stalled or OOM'd build holds the HTTP streaming response open forever, leaves the rebuild button disabled in the client with no way to cancel — `server/docker.js:100-110` — fix: add a `setTimeout`-based abort or pass `timeout` to spawn options, then emit a timeout error line and resolve `{ ok: false, code: -1 }`

- [ ] **[backend]** No file lock on crontab read-check-write — `POST /api/systems/:slug/crontab` reads the file, validates `expectedRawLine`, then writes; there is no lock between those two steps, so two concurrent edit requests can both pass the stale check and one silently overwrites the other — `server/server.js:143-158` — fix: use a per-slug async mutex or write to a temp file and rename atomically

## 🟡 Medium

- [ ] **[backend]** Container name used unquoted in shell commands — `containerCreatedAt` builds `docker inspect -f "{{.Created}}" ${container}` and `containerCrontab` builds `docker exec ${container} cat /etc/crontab.docker` without quoting; if a docker-compose.yml ever has a `container_name` with spaces or shell metacharacters, this is a command injection — `server/docker.js:77, 117` — low likelihood from trusted files but real; fix: quote the interpolation or pass the container name as a separate argv element via `spawn`

- [ ] **[backend]** `containerLogs` `|| stderr` fallback is dead code — the command passed to the runner is `docker logs --tail ${tail} ${container} 2>&1`, which redirects stderr to stdout before `execP` sees it, so `stderr` is always `''`; the `|| stderr` on line 93 can never contribute — `server/docker.js:93` — low consequence, but if the redirection is ever removed, the fallback becomes relevant; the current silent failure mode is fine once the dead branch is understood

- [ ] **[backend]** `discoverSystems` hammers the filesystem synchronously on every `/api/systems` poll — with 40+ sites, each 30-second tick does `readdirSync` + two `readFileSync` per site (crontab + docker-compose.yml) all synchronously on the main event loop thread, plus 40+ async `docker ps` calls; the sync portion blocks Node's I/O during a full scan — `server/discovery.js:76-87` — no cache, no debounce; could cause perceptible lag under concurrent requests

- [ ] **[frontend]** Auto-poll fires during diff modal — `applyPolling` suppresses the 30s tick when the log modal is open but does NOT check the diff modal; the tick calls `load()` which re-renders all cards while the diff overlay is visible — `server/public/app.js:451-459` — not destructive (modal stays on top) but the card DOM underneath is wholesale replaced; fix: add `if (!$('#diffModal').classList.contains('hidden')) return;` alongside the log check

- [ ] **[backend]** `containerStatus` back-compat wrapper maps `unknown` (docker daemon unreachable) to `'never-built'` — any caller that still uses the string wrapper (none in current code, but test coverage relies on it) would silently misreport a docker failure as "container was never built" — `server/docker.js:48-52` — low active risk since current callers use `inspectContainer` directly, but misleading if the wrapper is used in the future

## ⚪ Low

- [ ] **[backend]** `rebuildCron` uses `bash -lc` (login shell) for the compose invocation — loads `.bash_profile`/`.bashrc` inside the container which could have modified `PATH`, proxy vars, or other env side effects that affect the compose build — `server/docker.js:103` — `bash -c` (non-login) would be more predictable

- [ ] **[backend]** `FIELD_RE = /^[\d*,/-]+$/` rejects valid named cron tokens (`@reboot`, `@weekly`, `MON-FRI`, `JAN`) used by some supercronic/vixie-cron variants — `server/crontab.js:8` — no impact on the current crontabs which use only numeric notation, but a named token in a future entry would silently be excluded from the UI

- [ ] **[backend]** `cronContainerName` regex reads all `container_name:` values in docker-compose.yml and returns the first one ending in `-cron` — if a compose file has multiple services ending in `-cron`, it returns whichever appears first, not necessarily the actual cron service — `server/discovery.js:19-28` — currently one cron service per site, but fragile if that assumption breaks

- [ ] **[frontend]** `removeJob` relies on `postCrontab` calling `load()` implicitly; if `postCrontab` short-circuits on error (it returns early after the toast), `load()` is still called — but if the remove action errors out at the crontab layer (409 STALE), the UI shows an error toast and then calls `load()` anyway, which is the right behavior — minor: no refresh is needed on failure but it's harmless — `server/public/app.js:263-266`

- [ ] **[frontend]** No focus trap in log and diff modals — Tab key can escape the modal overlay and interact with cards behind it; mouse-outside-to-close works, but keyboard-only users can tab out accidentally — `server/public/index.html:56-110`
